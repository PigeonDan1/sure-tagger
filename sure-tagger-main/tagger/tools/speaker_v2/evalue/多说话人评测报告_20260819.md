# speaker_v2 多说话人评测报告

评测日期：2026-08-19  
评测对象：`tagger/tools/speaker_v2/evalue/data/` 中随机抽取的 100 组音频–tag 配对  
主要指标：`annotation[0].speaker.multi_speaker`

> 历史评测：本文冻结 2026-08-19 的 Sortformer/Pyannote/MOSS policy 与结果，不描述
> 当前生产链路。2026-09-10 起，其他、混合或未知语言的 ASR 使用
> Qwen3-ASR-0.6B，speaker timeline 使用官方 DiariZen；FireRedASR2-AED 仅用于
> 中英文单说话人共识。本文指标不能用作新路由的精度或覆盖率结论。

## 1. 结论

在 100 条音频上，speaker_v2 的 `multi_speaker` 推理全部成功。Ground truth 中有 3 条为 `null`，按要求不参与该字段统计，因此有效样本为 97 条：42 条多人、55 条非多人。

在这 97 条有效样本上，`multi_speaker` 结果为：

| 指标 | 结果 |
| --- | ---: |
| 覆盖率 | 100.00%（97/97） |
| TP / TN / FP / FN | 37 / 53 / 2 / 5 |
| Accuracy | 92.78% |
| Precision | 94.87% |
| Recall | 88.10% |
| F1 | 91.36% |
| Specificity | 96.36% |
| Balanced accuracy | 92.23% |

因此，这批数据上的主要结论是：多人检测准确率为 **92.78%**，F1 为 **91.36%**。误报 2 条，漏报 5 条。

## 2. 数据和 ground truth

- 总样本：100 条。
- 音频与 tag 按同名 stem 配对；每组包含一个 `.mp3` 和一个 `.json`。
- ground truth 来源：每个 JSON 的 `annotation[0].speaker`。
- `null` 只对对应字段排除，不会把整条样本从其它字段的统计中删除。
- `multi_speaker` ground truth 分布：`true=42`、`false=55`、`null=3`。
- 推理 manifest 不包含 tag、native metadata 或 transcript；标签仅在推理完成后用于计分，避免标签泄漏。

为规避 MP3 解码器在批量推理时的兼容性问题，运行使用了由原始 MP3 转换得到的临时评测副本：16 kHz、单声道、PCM WAV。原始 MP3 和 JSON 未修改。

## 3. 运行配置

- speaker_v2 profile：`quality-shadow`。
- 推理模式：历史 candidate 输出。2026-08-20 已移除 certification gate，新运行会直接写入 public adapter；本报告数值仍对应 2026-08-19 的冻结评测产物。
- `multi_speaker` primary：NVIDIA Streaming Sortformer 4-speaker v2；其 speaker count 以 `>=2` 派生。
- `speaker_change` primary：MOSS Transcribe-Diarize，Sortformer 作 fallback/recall witness。
- `speaker_overlap` primary：pyannote Community-1。
- 启用模型：MOSS、Sortformer、pyannote Community-1、FireRedVAD、ECAPA、Brouhaha；Whisper 和 CAM++ 按 profile 关闭。
- 为避免 RTX 2080 Ti 上 NeMo Sortformer 批量运行出现 CUDA illegal-memory-access，本次 Sortformer 使用 CPU；MOSS 使用 `cuda:1`，pyannote 使用 `cuda:0`，其余按 profile 使用 CPU。8 条并发 smoke 和完整 100 条任务均成功。

## 4. 各 speaker 字段结果

以下统计仍遵循“该字段 ground truth 为 `null` 则排除”的规则。`speaker_count` 和 `speaker_change_count` 使用 exact accuracy、MAE、RMSE；布尔字段使用 Accuracy、Precision、Recall、F1。

| 字段 | 有效样本 | 覆盖率 | 主要结果 |
| --- | ---: | ---: | --- |
| `multi_speaker` | 97 | 100.00% | Accuracy 92.78%，F1 91.36% |
| `speaker_count` | 97 | 100.00% | Exact 74.23%，MAE 0.340，RMSE 0.725 |
| `speaker_change` | 95 | 100.00% | Accuracy 82.11%，Precision 87.50%，Recall 74.47%，F1 80.46% |
| `speaker_change_count` | 85 | 100.00% | Exact 58.82%，MAE 1.071，RMSE 2.236 |
| `speaker_overlap` | 91 | 100.00% | Accuracy 67.03%，Precision 21.62%，Recall 88.89%，F1 34.78% |
| `overlap_ratio` | 72 | 97.22%（70/72） | MAE 0.0264，RMSE 0.0742 |

`speaker_overlap` 的正样本只有 9 条，且本次结果为 TP=8、FN=1、FP=29；因此虽然 recall 较高，precision/F1 明显偏低，应重点关注 overlap 的误报问题。

在 ground-truth `multi_speaker=true` 的 42 条样本子集上，`multi_speaker` 召回率为 88.10%（37/42）；这 42 条上的 speaker count exact accuracy 为 45.24%，MAE 为 0.714。后者是诊断性结果，不替代全体有效样本的 count 指标。

## 5. 可复现命令

在 `tagger/` 目录下执行：

```bash
# 生成不含 ground truth 的 WAV manifest
python3 tagger/tools/speaker_v2/evalue/evaluate_multi_speaker.py prepare \
  --data-dir tagger/tools/speaker_v2/evalue/data \
  --audio-dir tagger/tools/speaker_v2/evalue/audio_wav_16k_mono \
  --audio-extension .wav \
  --manifest tagger/tools/speaker_v2/evalue/manifest_wav.jsonl

# 运行 speaker_v2 quality-shadow
.runtime/speaker_orchestrator_py311_v1/bin/python \
  scripts/run_speaker_evidence_v2.py \
  --manifest tagger/tools/speaker_v2/evalue/manifest_wav.jsonl \
  --output-dir tagger/tools/speaker_v2/evalue/outputs/quality_shadow_wav_cpu_sortformer_100_20260819 \
  --profile quality-shadow \
  --workers 8 --model-workers 1 \
  --moss-device cuda:1 --moss-torch-dtype float16 \
  --sortformer-device cpu --pyannote-device cuda:0 --ecapa-device cpu \
  --resume

# 计分并生成 metrics.json、predictions.csv、predictions.jsonl
python3 tagger/tools/speaker_v2/evalue/evaluate_multi_speaker.py score \
  --data-dir tagger/tools/speaker_v2/evalue/data \
  --results tagger/tools/speaker_v2/evalue/outputs/quality_shadow_wav_cpu_sortformer_100_20260819/speaker_v2_shadow_results.jsonl \
  --output-dir tagger/tools/speaker_v2/evalue/outputs/quality_shadow_wav_cpu_sortformer_100_20260819/evaluation
```

## 7. 限制和解释

1. 这是从 3000 组数据中抽取的 100 组随机小样本，不是完整数据集评测；置信区间和分层误差分析尚未计算。
2. 这是 `quality-shadow` candidate 结果，`evaluation_output` 明确标记为 evaluation-only/unsafe-for-publication；不能直接当作 production 已认证指标。
3. Sortformer 本次采用 CPU 执行以规避当前 GPU/NeMo 运行时问题；如后续修复 GPU runtime，应重新跑一轮并比较结果。
4. 由于 overlap 正例很少（9 条），`speaker_overlap` 的 precision/F1 方差较大，当前结果更适合作为问题定位信号。
